이 문서는 **`index.html` 의 실제 CSS·SVG 에서 값을 뽑아 적은 것**입니다.
기억이나 인상이 아니라 측정값입니다. 대비는 계산했고, 크기는 파일에서 읽었습니다.

**쓰임.** 이 저장소의 대시보드뿐 아니라 **앞으로 만들 다른 화면**
(대가들의 선택, 다른 주제의 그래프)이 같은 얼굴을 갖게 하려는 문서입니다.
새 화면을 만들 때는 이 문서를 먼저 읽고, **여기 없는 재료를 새로 만들지 마세요.**
필요하면 이 문서에 먼저 추가하고 그다음에 쓰세요.

## 0. 한 문장

> **이 화면은 광고가 아니라 계기판이다.**

측량 도면과 계측기의 말투를 씁니다. 전고점은 **수위선**, 낙폭은 **빗금**,
화면 밖 전고점은 **파단선**. 종이에는 **모눈**이 깔려 있습니다.

이 말투에서 나오는 실무 규칙 셋입니다.

1. **숫자를 그림으로만 말하지 않습니다.** 눈금을 읽어 어림하게 두지 않고
   값을 옆에 그대로 적습니다(네 칸 계기판, 선 끝의 현재값).
2. **장식이 없습니다.** 둥근 모서리·그라디언트·색 버튼·그림자가 없습니다.
   예외는 떠 있는 것(툴팁·말풍선)뿐이고, 그건 "떠 있다"는 사실을 말하는 그림자입니다.
3. **여백이 설계의 일부입니다.** 빈자리를 채우려 들지 마세요.

## 1. 색

### 1-1. 중립 토큰 (측정된 대비)

```
--paper   #E9ECF0    바탕. 그 위에 56px 모눈을 깐다
--card    #FFFFFF    패널
--rule    #BCC6D0    경계선 (바깥 테두리)
--rule-2  #DDE3E9    경계선 (안쪽 칸막이·격자)
--ink     #0F1A24    본문 최고 대비
--ink-2   #475765    부제·보조
--ink-3   #68767F    캡션·각주
```

| 토큰 | 흰 카드 위 | 종이 바탕 위 |
|---|---|---|
| `--ink` | 17.59:1 | 14.85:1 |
| `--ink-2` | 7.45:1 | 6.29:1 |
| `--ink-3` | 5.47:1 | 4.61:1 |

**대비는 두 바탕에서 다 재세요.** 카드 위에만 글이 있는 게 아닙니다 —
`.eyebrow` `.stamp` `.support` `.foot` 넷은 **종이 위**에 있습니다. 1-4 참고.

**`--rule` 과 `--rule-2` 는 글자에 쓰지 마세요.** 1.73:1 / 1.29:1 이라 선으로만 씁니다.

### 1-2. 상승·하락 색은 언어를 따라 뒤집힙니다 ★ 가장 중요

| | 상승·탐욕 | 하락·공포 |
|---|---|---|
| `ko` `ja` `zh` | 빨강 `#C4362C` | 파랑 `#1F5FA9` |
| 그 밖의 언어 | 초록 `#1B7F4B` | 빨강 `#C4362C` |

**고정하면 정반대로 읽힙니다.** 미국 사용자에게 파란 하락선은 뜻이 안 통하고,
빨간 상승선은 폭락으로 보입니다.

구현은 `applyLang()` 이 `<html>` 에 CSS 변수를 꽂는 방식입니다.

```
--up  --down            색 자체
--up-rgb  --down-rgb    투명도를 섞을 자리 (예: rgba(var(--down-rgb),.05))
```

**새 화면에서 상승·하락을 칠할 때 `#C4362C` 같은 값을 직접 쓰지 마세요.**
반드시 `var(--up)` / `var(--down)` 입니다. 투명한 바탕이 필요하면
`rgba(var(--down-rgb), …)` 를 쓰세요 — 이걸 어기면 **글자만 뒤집히고 바탕은
안 뒤집히는** 상태가 됩니다(2026-09-13 에 실제로 났던 버그).

넷 다 흰 카드 위에서 5.02~6.43:1 이라 본문 크기에서도 AA 를 넘습니다.

### 1-3. 색을 쓰지 않는 자리

**파비콘·공유 카드·앱 아이콘은 무채색입니다.** 그림은 한 장인데 색 규칙은
언어마다 뒤집히므로, 올라가는 선을 칠하는 순간 한쪽 언어에서 반대로 읽힙니다.

**후원 링크 같은 행동 유도에도 색을 쓰지 않습니다.** 색 버튼은 이 화면에서
혼자 튑니다. 각주와 같은 크기·글꼴로 두고 **밑줄만** 남깁니다.

### 1-4. 한 바탕에서만 재면 틀립니다 (2026-09-14, 고침)

`--ink-3` 은 **흰 카드 위 기준으로만** 정해져 있었습니다(4.68:1, 통과).
그런데 그 색을 쓰는 글 중 넷은 카드 바깥, **종이 바탕 위**에 있었고
거기서는 **3.95:1 로 AA 미달**이었습니다.

```
.eyebrow   머리글의 브랜드 눈썹줄
.stamp     갱신 시각
.support   후원 한 줄
.foot      각주
```

`#68767F` → **`#5F6B74`** 로 내려 고쳤습니다(종이 4.61 · 카드 5.47).

**이 병은 전에도 한 번 있었습니다.** 그 전 값 `#8B99A6` 은 카드에서 2.91 이라
"글자 색깔이 눈에 띄지가 않아"는 지적을 받았고, 고친 `#68767F` 는 **또 카드만
보고** 정한 값이라 종이 위를 놓쳤습니다. **같은 실수를 두 번 했습니다.**

**색 토큰을 손볼 때는 렌더된 화면에서 실제 바탕을 찾아 재세요.**
CSS 만 읽으면 어떤 글이 어떤 바탕 위에 앉는지 안 보입니다. 조상을 거슬러
칠해진 바탕을 찾되, **반투명 바탕은 아래 색과 합성해야** 합니다 —
`rgba(196,54,44,.05)` 를 원색으로 읽으면 멀쩡한 칸이 대비 1.02 로 나옵니다
(검수 스크립트에서 실제로 그렇게 나와 한 번 헛짚었습니다).

## 2. 글꼴 — 세 벌, 각자의 일이 다릅니다

```
--mono   IBM Plex Mono            숫자 · 각주 · 기계가 찍은 값
--cond   IBM Plex Sans Condensed  제목 · 라벨 · 대문자 캡션
--body   Pretendard               문장
```

**규칙: 숫자는 mono, 이름표는 cond, 문장은 body.**

- **mono** — 자릿수가 같은 값끼리 세로줄이 서야 하는 모든 것. 계기판, 축,
  툴팁, 각주. 시각·날짜도 여기.
- **cond** — 제목과 **대문자 캡션**. 자간을 벌려 씁니다(`.1em`~`.16em`).
  좁아서 긴 라벨이 들어가고, 대문자로 쓰면 계측기 눈금판처럼 보입니다.
- **body** — 읽는 글. 설명 문단, 조건 문장.

**고정폭에서는 굵기 차이가 거의 안 보입니다.** mono 로 층을 나눌 때는
`font-weight` 말고 **크기와 색**으로 나누세요. 2026-09-13 에 캡션과 값이
전부 13px 한 덩어리였고 숫자는 굵기(500)만 달라서 "눈에 안 들어온다"는
지적을 받았습니다.

### 3-1. 바닥은 11px 입니다 (2026-09-17, `/titans/`)

위 표는 **대시보드**(`index.html`)의 값이고, 아래쪽이 9.5~11px 로 촘촘합니다.
사용자가 대가들의 선택 화면을 보고 **"어떤 글자 크기는 너무 작아. 제목은 적당한
거 같은데"** 라고 했습니다. 재 보니 각주 13문단이 **11px 고정폭**이었습니다 —
읽는 글로는 작습니다.

**널리 쓰는 바닥을 맞췄습니다.** 애플 HIG 는 *어떤 글자도 11pt 아래로 두지
말라*고 하고, 머티리얼의 제일 작은 칸(label small)도 **11sp** 입니다. WCAG 는
크기를 정해 두지 않으므로(1.4.4 는 200% 확대만 요구) **이 둘이 실질 기준**입니다.

그래서 `/titans/berkshire/` 는 **토큰 여섯 개**로 다시 짰습니다.

| 토큰 | 값 | 쓰는 곳 | 전 |
|---|---|---|---|
| `--t-micro` | **11px** | 대문자 이름표 · 축 날짜 · 막대 이름표 | 9.5~10 |
| `--t-label` | 11.5px | 칸 머리글 · 캡션 · 버튼 | 10~10.5 |
| `--t-small` | 12.5px | 섹터 · 순위 · 비중 | 10.5~11 |
| `--t-text` | **13.5px** | 읽는 글 — 각주 · 요약 한 줄 | 11 |
| `--t-num` | 14px | 표의 숫자 | 12 |
| `--t-name` | 16px | 종목 이름 | 15 |

**위쪽은 안 건드렸습니다** — 사용자가 제목은 괜찮다고 했습니다. 결과적으로
위아래 폭이 좁아져 화면이 한 덩어리로 읽힙니다.

**px 를 직접 적지 마세요.** 새 글자는 이 여섯 중에서 고릅니다 — 그래야 투자자를
더 넣어도 같은 얼굴입니다(아래 8번).

**크기를 올리면 칸 폭을 다시 재야 합니다.** 12px → 14px 로 올리자 영어 목록의
세로줄이 **18~23px 씩 흔들렸습니다**. 원인이 둘이었습니다.

- 최소 폭이 옛 크기 기준이었습니다 → 제일 긴 내용을 실제로 재서 다시 잡았습니다.
- **`.ret` 와 `.note` 의 폭이 서로 달랐습니다.** 가운데 칸이 `justify-content:
  center` 라, 셋째 칸만 넓은 줄이 섞이면 **덩어리 전체가 옆으로 밀립니다.**
  같은 자리에 번갈아 오는 칸은 **폭을 같게** 두세요.

**자리가 모자라면 되풀이되는 단위를 먼저 버리세요.** 글자를 키우자 영어 섹터가
둘째 줄로 밀려났는데, `227.9M shares` 의 `shares` 를 떼니 해결됐습니다 —
열 머리글이 이미 `SHARES HELD` 라고 적고 있었습니다(7번의 "열 머리에 한 번만").
한국어 `주` 는 못 뗍니다 — `2.28억` 만 남기면 무엇이 2.28억인지 알 수 없습니다.

**줄간격은 카드에서 상속받지 말고 다시 잡으세요.** 카드 전체가 1.7 인데
10.5px 캡션이 그걸 받으면 18px 상자를 차지합니다. 캡션 1.25~1.35, 큰 숫자 1.05~1.25.

## 4. 선 — 굵기와 점선은 뜻이 정해져 있습니다

### 굵기

```
1px      격자 · 축 · 테두리 · 칸막이 · 십자선
1.2px    전고점 수위선
1.3px    0% 기준선
1.6px    보조 가격선 · 빗금 획
1.7~1.8  십자선 점의 테두리
2px      범례 표본선
2.1px    강조 가격선 (지금 보고 있는 선)
2px      머리글 밑줄 — 화면에서 유일한 2px 경계
```

**선 하나를 굵게 해서 강조합니다.** 색을 더 쓰지 않습니다. 보조는 `--ink-2` 1.6px,
주인공은 `--down`/`--up` 2.1px.

### 점선 사전 — 같은 패턴에 같은 뜻

| 패턴 | 뜻 |
|---|---|
| `7 4` | **전고점 수위선** (도면의 기준 수위) |
| `2 2` + `opacity .5` | 선 끝에서 축까지 잇는 **안내선** |
| `2 3` | **십자선** 세로선 |
| `3 3` | 성적표에서 **지금 위치** 세로선 |
| `2 4` | 중립 기준선 (지수 50) |

**새 점선을 발명하지 마세요.** 뜻이 다른 선이 필요하면 이 표에 먼저 추가하세요.

### 눈금 표식 (2026-09-14 추가, `/titans/`)

점선이 아니라 **짧은 세로 획**입니다. 도면의 축척자에서 온 어휘라 새로 배울 것이 없습니다.

| 표식 | 뜻 | 값 |
|---|---|---|
| 줄 바닥의 짧은 세로 획 | **직전 분기의 비중** — 막대가 여기를 넘었는지 못 미쳤는지 | 11px · 1.2px solid `--ink-3` |
| 가로 자 + 눈금 | **연속 보유 기간** — 1년에 눈금 하나, 5년마다 길게 | 길이는 최장 보유에 비례, 최소 9px |

**직전 분기 표식을 줄 높이만큼 길게 긋지 마세요.** 처음에 `top:0;bottom:0` 으로
뒀더니 `Kraft Heinz` 의 글자 한가운데를 세로줄이 뚫고 지나갔습니다. 비중이 작은
종목일수록 표식이 이름 쪽으로 와서 잘 걸립니다. **줄 바닥에만 찍으세요.**

**자에 눈금을 찍는 간격에 문턱이 있습니다.** 1년당 2.6px 미만이면 눈금을 아예
생략하고 양 끝 캡만 남깁니다 — 6개월짜리 종목에 눈금을 우겨 넣으면 획이 뭉개져
선 하나로 보입니다(7번의 "띠가 좁으면 이름을 생략한다"와 같은 처리).

### 빗금 (낙폭)

```
pattern 6×6 · rotate(45°) · stroke-width 1.6 · var(--band-2)
--band-2 = rgba(var(--down-rgb), .18)
```

낙폭은 면을 채우지 않고 **빗금**입니다. 도면에서 "여기가 깎여 있다"를 뜻합니다.
언어를 따라 색이 뒤집히도록 `--down-rgb` 를 씁니다.

### 구간 색 띠

`rgba(색, 아주 낮은 투명도)` 로 **아주 옅게**만 깔고, 이름표는 cond 대문자입니다.
띠가 좁으면 이름을 **자동으로 생략**합니다 — 문턱은 고정 px 가 아니라
`MINH = max(16, 차트높이 × 0.075)` 입니다. **차트 높이를 바꾸면 이 값도 같이 움직입니다.**

## 5. 면 — 카드, 테두리, 여백

```
.panel   background var(--card) · border 1px var(--rule) · margin-bottom 20px
         border-radius 없음 · box-shadow 없음
```

**둥근 모서리가 없습니다.** 동그라미는 딱 둘 — ⓘ 버튼과 실시간 표시등입니다.

**그림자는 떠 있는 것에만.**

```
툴팁    0 2px 10px rgba(15,26,36,.10)
말풍선  0 6px 20px rgba(0,0,0,.12)
```

### 좌우 여백의 박자

```
바깥 폭   max-width 900px
페이지    36px 20px 72px   (모바일 24 / 14 / 56)
카드 안   20px             (모바일 14px)
```

**카드 안쪽 왼쪽 선은 20px 하나입니다.** 글도 차트도 계기판도 전부 거기서 시작합니다.
차트만 8px 이라 혼자 튀어나와 있던 적이 있습니다.

**SVG 여백은 하드코딩하지 말고 `getComputedStyle` 로 실제 padding 을 재세요**
(`geo()`). 카드 padding 을 바꿨을 때 차트만 어긋납니다.

### 종이의 모눈 — 이 사이트의 서명

```css
background-image:
  linear-gradient(rgba(15,26,36,.028) 1px,transparent 1px),
  linear-gradient(90deg,rgba(15,26,36,.028) 1px,transparent 1px);
background-size:56px 56px;
```

**새 페이지도 이 모눈 위에 올리세요.** 이것 하나로 같은 집 화면으로 보입니다.

### 차트 오른쪽 여백은 세 층입니다

```
[ 그리는 영역 ][ 선 끝의 현재값 ][ 축 숫자 ][ 구간 이름 ]
                    labW 52         numW 26    nameW ≤96
```

**구간 이름 자리는 실제 글자 길이로 잽니다.** 영어 `EXTREME GREED` 가
한글 `극단적 탐욕` 보다 훨씬 길어서, 고정폭으로 두면 차트 밖으로 나갑니다.

## 6. 여백은 상자가 아니라 잉크로 재세요 ★

큰 글자 아래 간격을 손볼 때 `getBoundingClientRect()` 만 보면 틀립니다.

38px 숫자 `33` 의 줄 상자는 **글자보다 8px 쯤 아래로 더 내려옵니다**
(내려긋는 획이 없으니까요). 그래서 상자 사이를 6.4px 로 붙여 놔도
**눈에는 14px** 로 보입니다.

```
상자로 재기   getBoundingClientRect()            ← 이 8px 이 안 보임
잉크로 재기   canvas actualBoundingBoxAscent/Descent   ← 여기서 나옴
```

해결은 음수 여백으로 그 몫을 도로 먹는 것입니다(`margin-bottom:-3px`).

## 9. 움직임

**최초 1회만.** 1.6초 뒤 `body.settled` 가 붙고 그 뒤로는 애니메이션이 없습니다.
다시 그릴 때마다 선이 살아나면 계기판이 아니라 광고가 됩니다.

```
.draw   선이 그려짐 — stroke-dasharray 로 .9s
.fade   나타남 — .5s
.d1 .d2 .d3   순서 지연 .45s / .7s / .9s
```

**선 그리기는 `getTotalLength()` 로 실제 길이를 재야 합니다**(`calibrateDraw()`).
안 재면 선이 중간에 끊겨 보입니다 — **새 차트를 추가하면 반드시 부르세요.**

```css
@media (prefers-reduced-motion:reduce){ /* 전부 끈다 */ }
```

**실시간 표시등만 예외로 계속 깜빡입니다**(`blip` 2.4s). 이것도 reduce 에서는 멈춥니다.

## 10. 접근성

- **초점 표시는 `outline:2px solid var(--ink); outline-offset:2px`** 로 통일합니다.
  hover 와 **달라 보여야** 합니다 — 둘을 한 줄에 묶어 두면 키보드 사용자가
  자기가 어디 있는지 모릅니다.
- **켜고 끄는 버튼은 `aria-pressed`** 로 표시하고, 눌린 것은 `background:var(--ink); color:#fff`.
- **버튼은 한 번만 만들고 이후엔 `aria-pressed` 만 옮깁니다.** 매번 다시 그리면
  방금 누른 버튼이 사라져 초점을 잃습니다. (예외: 언어를 바꾸면 글자가 바뀌므로 다시 그립니다.)
- **본문 대비는 AA(4.5:1)** 를 넘깁니다. 1-1 의 표로 확인하세요.
- **면책·경고 문구는 본문과 같은 크기·글꼴로.** 작게 흘려 쓰면 제일 중요한
  문장이 제일 안 읽힙니다.

## 12-2. 투자자 화면은 틀입니다 (2026-09-17)

`/titans/shared/investor.css`와 `/titans/shared/investor.js`가 모든 투자자 화면의
**단일 공통 틀**입니다. 사용자가 못박았습니다 — *"다른 투자자를 추가할 때마다
같은 서식으로 해야 하거든. 앞으로 모든 수정은 이 점을 감안해야 해."*

`/titans/berkshire/index.html`에는 버크셔 고유 설정과 검색엔진이 JavaScript 없이도
읽을 영문 제목·설명만 남습니다. 화면 구조·한국어/영어 문구·디자인·차트·계산은
공통 두 파일에서만 관리합니다. 이후 디자인을 바꿀 때 투자자 폴더를 순회하며
복사하거나 같은 수정을 되풀이하지 않습니다.

**한 명 더 넣는 방법**

```
1  titans/berkshire/index.html의 짧은 투자자 껍데기만 복사 → titans/<slug>/index.html
2  <head> 의 canonical·hreflang·og:url·title·description 및 정적 h1·소개를 새 투자자로
3  window.TITAN 블록의 설정을 고친다. 공통 CSS·JS 경로는 그대로 둔다
4  scripts/fetch_13f.py 의 CIK·OUT 을 그 투자자로 → data/titans/<slug>.json
5  sitemap.xml 에 줄 하나 (표식 주석을 꼭 달 것 — CLAUDE.md 6-2)
```

```js
window.TITAN = {
  slug : "berkshire",                          // 주소의 폴더 이름
  cik  : "0001067983",                         // 각주에 그대로 찍힘
  data : "../../data/titans/berkshire.json",   // 공시 JSON 자리
  name : { en:"Berkshire Hathaway", ko:"버크셔 해서웨이" },
  since: 1998,                                 // 자료의 첫 해
  prices: "../../data/titans/prices.json"       // 투자자들이 공유하는 일별 가격
};
```

실행 후 제목·설명·`h1`·`canonical`·각주는 이 블록에서 나옵니다. 사전 항목이
문자열이 아니라 **함수**(`docTitle:(n,y)=>…`)인 이유가 그것입니다. 정적 원본의
영문 제목·설명·`h1`·소개는 검색엔진을 위해 투자자 페이지에도 직접 둡니다.

**틀이 실제로 도는지 확인하는 방법**: 별도 투자자 설정으로 공통 JS를 실행하고
이름·제목·`h1`·`canonical`·각주·계산이 따라오는지 검사합니다. 2026-09-19에는
`Example Capital/샘플 투자사` 설정과 실제 버크셔 자료로 공통 계산까지 재 봤습니다.

**간판에는 법인 이름을 씁니다.** 살아 있는 사람 이름을 주소·도메인에 넣지
않는다는 규칙(CLAUDE.md 9번)이 **화면 글자에도** 걸립니다.

**앞으로 이 화면을 고칠 때는 "버크셔에서 맞나"가 아니라 "여덟 명 누구에게나
맞나"로 보세요.** 손으로 적은 회사 이름·연도·숫자는 곧 다음 투자자에서
거짓말이 됩니다 — 각주의 분할 목록을 자료에서 뽑게 고친 것과 같은 이유입니다.

**소개와 모바일 숫자 안내 (2026-09-18).** 머리글 아래 소개는 읽는 글 토큰
`--t-text`와 `--ink-2`를 씁니다. 정적 영어 본문을 남기고 실행 후 사전의
`intro(n)`가 설정된 투자자 이름·언어를 채웁니다. 모바일은 열 머리글 대신
목록 위에 숫자 순서를 한 번만 안내합니다(`--t-small`, `--ink-2`). 같은
라벨을 매 줄 되풀이하지 않습니다. 요약 계기판 이름표는 모바일도 `--t-micro`(11px).
실제 동작·검증은 `CLAUDE.md` 9-3-1의 개선 권장 후속 항목을 봅니다.

**가격선과 매매 막대 (2026-09-18).** 가격선 위에 거래 상자를 얹지 않습니다.
X축에서 매수·매도 모두 위로 그리며 기존 `--up/--down`으로 구분합니다. 높이는
절대 수량 변화에 비례, 최대 34.5px(차트 폭 430px 미만 27px). 막대는 해당 분기
전체 폭이며 1년 창에도 같은 규칙입니다. 이전 거래 카드는 제목·매수·매도 세 줄,
숫자는 방향 색. 차트 제목·부제·아래 중복 캡션은 넣지 않습니다. 날짜 눈금과 수량
이름표 수는 화면 폭에 맞추되 글자 토큰을 줄이지 않습니다. 점선과 날짜·가격
말풍선은 마우스와 터치에 대응하고 창 안에 맞춥니다. 모바일 목록 숫자는 칸 사이에서
줄바꿈합니다. 일별 가격을 연결한 뒤 창 끝은 최신 저장 종가 날짜이며, 실제 날짜
간격을 씁니다. 여러 종류를 합친 줄은 대표 종류의 티커를 말풍선에 표시합니다.
상장 전 값이나 공시 이후 매매는 만들지 않습니다. 가격 기준 설명은 각주에만 두며
차트에 제목·캡션을 다시 넣지 않습니다. 실제 데이터 경로와 제약은 `CLAUDE.md`
